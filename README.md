# Учёт подписок клиентов

Приложение на Onno Framework: клиенты, тарифы, платежи и подписки с учётом баланса и выручки.
Схему PostgreSQL, CRUD API и интерфейс генерирует Onno из Java-метамодели.

**Стек:** Java 21, Spring Boot 3.4.4, Onno 3.4.1, Gradle 8.14.4, PostgreSQL 17.

## Возможности

- Справочники клиентов и тарифов, подписка на несколько тарифов.
- Расчёт стоимости и даты окончания по максимальному сроку строки.
- Проведение платежей и подписок, проверка средств, отмена и перепроведение без дублей.
- Лицевые счета клиентов и регистр выручки по клиентам и тарифам.
- Автоматическое обновление статусов каждый час и после запуска приложения.
- Дашборд с выбором периода, показателями, диаграммами и последними документами.
- Отмена подписки из списка или карточки с обязательной причиной и возвратом списания.

## Запуск

Нужны JDK 21 и работающий Docker. Команды выполняются из корня проекта.

1. Скопируйте `.env.example` в `.env` и замените значения `CHANGE_ME`:
   пароль PostgreSQL, пароль администратора и ключ remember-me.

   ```sh
   cp .env.example .env
   ```

2. Запустите базу и приложение:

   ```sh
   docker compose up -d --wait
   ./gradlew bootRun --no-daemon
   ```

3. Откройте [localhost:8080](http://localhost:8080/).
   Логин и пароль — `ONNO_ADMIN_USERNAME` и `ONNO_ADMIN_PASSWORD` из `.env`.

На Windows используйте установленный Gradle 8.14.4: `gradle bootRun --no-daemon`.
Для запуска из IntelliJ IDEA выберите JDK 21 и класс `OnnoSubscriptionsApplication`.
Рабочая директория — корень проекта, где лежит `.env`.
Запускайте один экземпляр приложения; порт по умолчанию — 8080.

Демонстрационные данные автоматически не создаются. Данные базы сохраняются в Docker volume.

## Работа с приложением

Создайте клиента и доступные тарифы, затем оформите платёж и подписку с нужными строками.
**«Записать»** сохраняет документ и рассчитывает поля подписки; **«Провести»** отражает
операцию в регистрах: платёж пополняет счёт, подписка списывает деньги и создаёт выручку.
При недостатке средств проведение подписки отклоняется.

Остатки доступны в **«Лицевые счета»**, движения — в **«Выручка»**, сводные показатели —
в **«Обзор»** с выбором периода. Для отмены подписки выберите **«Отменить подписку»**
в списке или меню карточки и укажите причину: списание возвращается на счёт, выручка отменяется.

## Архитектура

Бизнес-модель описана аннотациями Onno и типизированными ссылками `Ref<T>`:

- `domain` — справочники `Customer`, `Tariff`; документы `Payment`, `Subscription`;
  строки подписки `SubscriptionLine` и перечисления статусов.
- `CustomerAccount` — регистр остатков по клиентам; `Revenue` — регистр оборотов
  по клиентам и тарифам. Платёж пополняет счёт, подписка списывает средства и создаёт выручку.
- `service` — расчёты, бизнес-проверки и отмена подписки. Правила подключены к жизненному
  циклу документов; финансовые движения выполняются транзакционным механизмом Onno.
- `repository` — типизированные репозитории Onno и обновление статуса с проверкой версии,
  без пересчёта стоимости и перезаписи строк.
- `jobs` — фоновое обновление статусов через JobRunr.
- `ui` — формы и списки через `EntityView`, навигация через `Layout`, дашборд через `Page`,
  отмена с причиной через `ActionSpec`.

Onno создаёт схему и генерирует REST API; собственных CRUD-контроллеров нет.
Авторизация — сессия и роль `ADMIN` через `onno-auth-starter`.
