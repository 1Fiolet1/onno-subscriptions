# Подготовка и демонстрация решения

## Что передать

ТЗ требует ссылку на публичный GitHub-репозиторий с Java-решением и README.
Локальная реализация обязательных требований завершена; публикация репозитория и отправка
ссылки ещё не выполнены. В репозиторий должны попасть исходники, тесты, Gradle Wrapper,
`compose.yaml`, `.env.example`, README и документация. Локальный `.env`, рабочая база,
логи и результаты сборки туда не входят.

Для просмотра и передачи исходников можно собрать архив:

```sh
./gradlew sourceBundle --no-daemon
```

Результат: `build/distributions/onno-subscriptions-source.zip`.
Архив содержит проект и инструкции, включая установленный набор Onno Skills.
Получатель распаковывает его и выполняет раздел «Локальный запуск» в README.
Это вспомогательный артефакт; для сдачи по ТЗ всё равно нужна ссылка на GitHub.

## Проверка на машине проверяющего

1. Установить JDK 21, запустить Docker с Docker Compose.
2. Скопировать `.env.example` в `.env`, задать свои пароли и ключ remember-me.
3. Выполнить `docker compose up -d --wait`.
4. Выполнить `./gradlew clean build --no-daemon`: 36 тестов используют временную базу.
5. Запустить `java -jar build/libs/onno-subscriptions-0.0.1-SNAPSHOT.jar` из корня проекта.
6. Открыть `http://127.0.0.1:8080/`, войти по своим значениям из `.env`.

Первый запуск не добавляет демонстрационные бизнес-данные автоматически.
Схему, формы и API создаёт Onno. Docker volume сохраняет рабочие данные после остановки базы.

## Сценарий демонстрации через интерфейс

Использовать отдельного тестового клиента, чтобы его баланс был изначально нулевым.

1. Создать клиента «Демо — проверка», указать корректный e-mail, например `demo@example.com`.
2. Создать доступные тарифы: «Месячный» — 100 ₽ за 30 дней;
   «Годовой» — 1 000 ₽ за 365 дней.
3. Создать подписку этому клиенту: 2 периода месячного и 1 период годового тарифа.
   После записи итог — 1 200 ₽, окончание — начало + 365 дней, статус — «Черновик».
   Поля цены и суммы пересчитывает сервер при записи.
4. Попытаться провести: отказ из-за недостатка средств; баланс и выручка не меняются.
5. Создать платёж на 2 000 ₽ и провести: в «Лицевые счета» остаток 2 000 ₽.
6. Провести подписку: остаток 800 ₽, в «Выручка» два движения — 200 ₽ / 2 периода
   и 1 000 ₽ / 1 период. Повторное перепроведение сохраняет эти значения без дублей.
7. Отменить проведение подписки: остаток 2 000 ₽, её активная выручка отсутствует.
   Если пункт отсутствует в меню сразу после проведения, обновить карточку.
8. Снова провести подписку и выбрать «Отменить подписку» в меню карточки. Указать причину:
   остаток вернётся к 2 000 ₽, статус станет «Отменена», причина сохранится, выручки нет.
   То же действие доступно в меню строки списка.
9. Для проверки задания создать ещё одну подписку, оставить «Черновик», выбрать сегодняшнее
   начало и провести. После очередной фоновой проверки обновить список: статус «Активна».
   Проверка запускается каждый час и после запуска приложения; даты считаются по Москве.
10. Открыть «Обзор», выбрать период с документами и пустой период: показатели и диаграммы
    обновляются; текущие остатки и последние документы не ограничиваются периодом.
11. Остановить и снова запустить приложение, убедиться, что документы и остатки сохранены.

Границы окончания срока, отклонение некорректных строк, отмена и финансовые транзакции
проверены автоматически; для демонстрации истечения срока не требуется ждать окончания тарифа.

## Что объяснить на собеседовании

- Справочники описывают клиентов и тарифы; документы — платежи и покупки подписок.
- Табличная часть позволяет купить несколько тарифов в одном документе.
- Регистр `CustomerAccount` хранит остаток по клиенту, `Revenue` — обороты по тарифу и клиенту.
- Запись рассчитывает данные; проведение в транзакции создаёт финансовые движения.
- Срок определяется максимумом `длительность тарифа × периоды`, суммы складываются.
- Цена фиксируется в документе при оформлении; при смене тарифа подставляется новая цена.
- Проверка средств учитывает старое списание при перепроведении; Onno дополнительно
  проверяет итоговый остаток внутри транзакции для одновременных покупок.
- Статус срока и признак проведения — отдельные поля. Истечение срока не возвращает оплату.
- Фоновая задача меняет только статус и версию; условия записи защищают от одновременных изменений.
- Onno генерирует схему, CRUD API и интерфейс. Единственный частичный запрос приложения
  нужен для смены статуса без пересчёта и перезаписи строк.
